## Exact method and limits of inference

Each fresh temp root contains 128 small imported requests/versions/lineages in a validated authoring v2 index, plus one local maximum-source request revising a 512 KiB imported parent. The source packet is exactly2097152 canonical UTF8 bytes with1000 message refs; Markdown/parent are524288 bytes. Existing real managed CLI/API fixtures supply authenticated bindings and real brief/outbox/queue files; process birth/open/Popen observations are test doubles. Real atomic_json, file reads, packet canonicalization, index validation and fsync execute. No provider, native client, server installation or network acceptance. Request count129, including128 small priors; index bytes are recorded per sample. One harmless unused template packet is an explicit setup orphan, not a diagnostic body. Each fixture root is removed and asserted absent after cleanup.

A uses the actual current public service entries with the existing boundary. The brief_context case invokes the actual current get_parent + get_brief pair inside one outer boundary, as the MCP tool does; it includes parent bytes and activation. Diagnostic-bearing branches stop at a harness-only DiagnosticStop before any diagnostic IO, retaining all earlier service work and a detached guard-copy/hash cost. submit_cli uses invalid blank512KiB text; admit_saved uses a sealed conflicting512KiB result; reject_response uses a512KiB report; lost-ACK repair uses a real committed version and a sealed conflicting retained result. Startup uses the actual recover_startup scan through a cancelled saved result. resume/recovered use an explicit late-read fault seam: get_packet fully reads/parses/validates the healthy2MiB packet THEN raises ArtifactUnavailable. This profiles the expensive read plus failure path, not a physically corrupt-packet history. A diagnostic stop must be reached, except the healthy context/delivery cases, or the harness refuses the sample.

C_probe is a prospective feasibility probe, NOT implemented D4: it re-reads/canonicalizes/hashes the current row, obtains fresh queue state, runs existing _context or retained recovery/ACK checks, and for terminal continuations performs real set_attempt_state plus deterministic queue fence. Startup probes actual sealed outbox verification and disposition write with a harness-only id inside a disposable root; no durable diagnostic was falsely claimed to a product caller. Nonterminal probes end after their authority checks. The complete future immutable intent/receipt/continuation comparisons and actual driver are absent, so C_probe is a lower-bound feasibility observation, not a claim that future phase C passes. No B or peers are measured, so this cannot certify final A/B/C concurrency.

packet_reads_A/C count the public get_packet API wrapper, not internal store._packet calls: brief_context reports2 API reads plus the real internal activation read; the current combined path therefore performs3 packet validations. contexts counts existing _context invocations. Wrapper and guard-copy overhead is retained. No CPU attribution or performance extrapolation. Each sample is kept, without favorable reruns.
