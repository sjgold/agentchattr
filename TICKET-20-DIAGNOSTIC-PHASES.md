# Ticket 20 R2 D4: diagnostics outside the authority boundary

Status: PROPOSED CONTRACT, docs only. Reviewer review is required before D4 reds or source edits. This amends the diagnostic-bearing service paths in [the R2 owner contract](TICKET-20-DIAGNOSTICS.md); it does not clear R2. D1 inventory and D2 byte-identical shared JSON writing remain. R3, operator routes, capacity, activation and push remain held.

## Why the boundary changes

The one fresh D1/D2 production gate at product/tool pin 7fe71f7 failed. Heavy writes had median 0.228606800 s and maximum hold/peer 0.386682400/0.386908700 s; samples 8 and 9 missed 0.270 s and only one of ten met the 0.216 s margin. Structural reads also missed, at 0.270486300/0.271032500 s in sample 8. Summary and both import selections passed. Every replace-retry counter was zero. These are NORMAL misses, with no excluded samples or replacement run. [All 50 samples and phase summaries](TICKET-20-DIAGNOSTICS-D1-D2-GATE.md) are retained separately from the original failed gate and instrumented profile.

The reviewer selected D4 instead of D3 evidence reuse: diagnostic disk/validation/inventory work leaves the engine and catalog boundary. Neither the 0.270 s hard limit nor retained-state budgets change. No claim about the cause of an individual historical outlier follows from the correlation between the two sample-8 misses.

## Ownership and phases

Each affected public service call is an orchestrator that starts without a caller-held engine/catalog boundary. Healthy paths needing no diagnostic keep their existing guarded behavior. A diagnostic branch has these phases:

|Phase|Locks and work|Permitted effects|
|---|---|---|
|A, capture|Engine + catalog boundary, existing authoring reads and authority checks; a memory-only attachment snapshot under the authoring RLock|Existing activation to ACTIVE may already have happened. Capture a detached immutable intent and continuation. No diagnostic owner lock, diagnostic read/write, new terminal transition, result disposition or diagnostic-dependent ACK.|
|B, persist|Outside engine/catalog and authoring locks. Diagnostic RLock + existing diagnostic process lock + body process lock|Full graph validation, encoded-cap checks, inventory, body put, metadata fsync/replace and durable receipt, exactly through the current diagnostic owner. No authority callback or boundary entry.|
|C, settle|Re-enter engine + catalog boundary, re-read current request/claim/authority and the retained result when relevant|Only after a durable receipt and successful revalidation, finish the captured continuation. No diagnostic owner read, lock, report or write.|

Release all A locks before B, and release all B locks before entering C. A failure in B returns the existing typed diagnostic unavailability, with no C effect or fabricated diagnostic id. A durable B followed by C refusal leaves a genuine retained diagnostic and no stale state transition. Diagnostics are evidence of an observation, never authority to admit a version, cancel a request or repair an ACK.

No lock-release trick on an outer RLock is allowed. In particular, releasing a service's nested `with` while its caller still owns the boundary does not implement this contract.

## Private mechanism and signatures

All types below are private to the existing modules. No new public route, persisted plan, journal, ContextVar evidence or client-supplied receipt is added. Exact source names proposed for the reds:

|Name|Shape and responsibility|
|---|---|
|`_DiagnosticIntent`|Frozen dataclass of scalar immutable fields: diagnostic key request_id (Hex32 or null), attempt_id, dispatch_id, actor_identity_id (Hex32 or null), closed existing quarantine reason, bounded content (str or null), captured attachment (Hex32 or null), received_truncated (bool), and `now` (captured finite R1 number). It also holds `_DiagnosticGuard` and `_DiagnosticContinuation`, both frozen. No dict/list reference from store, registry, queue or outbox is retained.|
|`_DiagnosticGuard`|Authority target request_id (distinct from the diagnostic key), exact canonical audit bytes, request state/reason/version_id/current channel, immutable queue claim projection, and mode. Queue projection contains state, consumer_id, cancellation_id, stop_id and canonical envelope bytes. Result-based paths also retain the verified sealed record digest and ACK/disposition absence or value. For an unmatched target, retain both lookup ids and their absence. Canonical bytes use existing ensure_ascii=True/allow_nan=False/default separators with sorted keys for comparisons only; no persisted encoding changes.|
|Guard modes|`live_claim`, `fulfilled_replay`, `retained_recovery`, `terminal_saved`, `unmatched_saved`. The latter two use retained managed-launch authority rather than demanding a current live worker. They never authorize an admission.|
|`_DiagnosticContinuation`|Closed effect kind plus immutable context: `return_quarantine`, `raise_invalid_content`, `fail_source_packet`, `quarantine_invalid_response`, `resume_ack_conflict`, or `startup_saved_disposition`. Also identify caller category agent/resume/startup for changed-state projection, and original error family for source failure. No arbitrary callable is stored in an intent.|
|`_DiagnosticRequired(Exception)`|Internal control-flow signal carrying one frozen intent. It inherits directly from Exception, not ValueError/RuntimeError, and is caught explicitly at the orchestrator. It never reaches HTTP/MCP/worker error projection. Existing broad catches must not convert it to a storage error or successful recovery.|
|`ArtifactService._run_diagnostic_operation(step)`|Private invocation-local driver. Run the caller's capture step once under A. If it returns normally, return its existing result. If it raises `_DiagnosticRequired`, exit A, call `_persist_diagnostic_intent(intent)` once, then `_settle_diagnostic_intent(intent, receipt)` under C. Never rerun the whole operation or perform an automatic second diagnostic attempt. The step is a private synchronous function, not user data.|
|`ArtifactService._persist_diagnostic_intent(intent)`|B only. Validate intent type, call `store.diagnostic_store.record` with the captured key/content/attachment/time, and return canonical immutable bytes of its detached row/summary. The driver then wraps those bytes in `_DiagnosticReceipt`. Do not use the facade `quarantine_submission`, which takes an authoring snapshot.|
|`_DiagnosticReceipt`|Frozen invocation-local wrapper binding the exact intent object and a fresh driver-local object token to immutable copies of the returned row/summary fields needed by the existing result builder. The driver wraps B's returned value; the token never lives on an owner or in a diagnostic row. Not accepted by a public method. No lookup by a caller-provided diagnostic id. Preserve the current receipt-id selection, including an overflow summary's own id.|
|`ArtifactService._settle_diagnostic_intent(intent, receipt, *, invocation_key)`|C only. Verify token identity and exact intent identity against the driver's current locals, revalidate the guard, execute the closed continuation or the changed-state outcome below. It never calls record/report/request_diagnostics and never resumes capture implicitly.|
|`ArtifactService.get_brief_context(brief_id, instance)`|New internal service entry for the real MCP tool. Within A, validate/read parent first, then perform the same brief capture/activation. Return the existing merged brief/packet/parent dictionary. The MCP wrapper serializes it and enforces the existing MAX_CONTEXT_BYTES limit outside the boundary. A refused parent still prevents activation; context-limit behavior after activation is preserved.|

`_packet` and `_diagnostic` become capture-only private helpers when called by an orchestrator: they raise the private signal with an explicit continuation instead of doing B inside A. They must capture the current store row after any activation, not the possibly stale local variable in `admit_saved` (which currently ignores `_activate`'s returned row). Capture records only the branch actually reached; it cannot turn a source failure into an invalid-response intent.

Private brief seals, launch refs and audit bytes stay invocation-local and retain existing privacy rules. They are never added to a diagnostic row, response, exception text, timing receipt or log. The intent's diagnostic key may come from a wrong-scope payload; its authority target is always the independently looked-up current request. Capture must not let a claimed request id select a different authority guard.

## Attachment and legacy-marker lock edge

The store gains `_capture_diagnostic_attachment(request_id, dispatch_id)` returning the same Hex32-or-null first-attachment decision from cached memory under the authoring RLock only. It checks cached authoring held/known/legacy state, performs no file IO and never takes the diagnostic RLock. Non-null held authoring raises ArtifactUnavailable with the existing authoring text. A null diagnostic key needs no healthy authoring owner, except for the sticky legacy rule. Imported requests do not attach.

The current facade snapshot calls `_set_legacy_hold`, which takes the diagnostic RLock. Service capture must not use that edge. A private shared `threading.Event`, `_diagnostic_legacy_marker`, conveys only the sticky development-v1 hold between the two owners. Create it before constructing the diagnostic owner; set it when the authoring constructor, `_check_index` or `_persist` discovers legacy nonempty v1. Setting the event never takes the diagnostic lock. Both owners remain sticky until a fresh owner after explicit offline repair, as already frozen.

The proposed diagnostic constructor becomes `ArtifactDiagnosticStore(data_dir, *, hold_unreadable=False, legacy_held=False, _legacy_marker=None)`. The optional private marker is an Event or null; standalone owners create their own marker, and legacy_held=True sets it. ArtifactStore passes its shared marker. Report/error state derives legacy-held from that marker as well as the existing local flag, so capture need not synchronize it by acquiring the diagnostic lock. This is a private in-memory coordination change, not a schema field or a data migration.

The diagnostic owner tests that marker within its transaction before accepting a new write, and before body/metadata publication. Its existing legacy-held error/report takes precedence. A marker observed before B refuses B without creating diagnostics.json or copying old diagnostic rows. A legacy change discovered concurrently with an already executing filesystem replace is a cross-file fault seam, not a rollback transaction: preserve any landed bytes, mark the diagnostic owner held, refuse C, and never reset/merge the old index. Add an Event test for this seam; do not claim atomicity across the two files. The ordinary standalone facade remains usable outside a boundary and preserves its R2 typed projections.

## C guard and changed-state outcomes

For live work, C rechecks capability, the authenticated identity/binding, private brief ownership, active current channel, queue envelope/consumer/fences, exact audit and row state/reason/version/channel. For retained recovery, keep the existing sealed-result/managed-launch and recovery-proof rules; do not add a live-worker requirement to fulfilled lost-ACK repair. Parent/source/content snapshots are immutable, but request state and authority are re-read. A recorded bad-packet observation need not be re-read from disk in C; repairing that file during B does not erase the diagnostic or change the historical failure branch.

|Observed at C|Agent callers (`get_brief`, delivery, submit, admit, reject)|Operator `resume_request`|Startup recovery|
|---|---|---|---|
|All guard fields unchanged|Execute original continuation below|Execute original continuation and existing MutationResult|Execute original continuation and append only its real effect|
|Cancel or Stop won, including new cancellation/stop fence while row still live|Existing ArtifactConflict, public 409 artifact_conflict; no stale activation, terminal overwrite, ACK or disposition|Return current row/transport through existing MutationResult, no admission; warning operator_recovery_required only while transport effects remain unconfirmed|Re-read cancelled row and use existing cancel-fence repair branch, then leave saved-result disposition for a later fresh pass. Otherwise held/operator_recovery_required. No admission.|
|Another writer fulfilled or otherwise made row terminal|409 artifact_conflict, even if its state happens to equal the proposed terminal effect. A state alone cannot prove our diagnostic was applied.|Return current terminal MutationResult, admission null, warning operator_recovery_required for interrupted recovery; do not fabricate a lost-ACK repair|Held/operator_recovery_required for this item. A subsequent pass may perform the ordinary fulfilled ACK-repair path after fresh verification.|
|Other live change, including queued-to-active, reason/channel change, another claim or a different result/disposition|409 artifact_conflict; retained diagnostic only|ArtifactConflict, no mutation|Held/operator_recovery_required; stop this item|
|Producer gone, replaced or binding changed|Existing access/binding error classification, 403 for absent authenticated authority or 409 _ArtifactProducerUnavailable for changed binding|Existing producer refusal, no mutation|Held/producer_unavailable where the branch requires a live producer; retained-only modes remain independent of worker liveness|
|Target removed, lookup formerly absent now matches, or audit/attempt changed|409 artifact_conflict; no attachment rewrite|ArtifactConflict|Held/operator_recovery_required|
|Authoring/brief/result/queue storage cannot be verified|Existing ArtifactUnavailable/storage 503, no C effect|Same typed storage refusal|Existing held/storage_unavailable, except fulfilled ACK-repair's existing inner mapping to operator_recovery_required|

Exact-state matching is deliberately conservative. No same-call retry, row-order-based fallback, automatic cancellation of another writer, or conversion of a conflict into a successful quarantine. The genuine B receipt remains in diagnostics but is not returned as a successful result when C refuses. Existing public fixed transport strings and shapes stay unchanged; no operator-package DTO/reason is introduced.

Normal paths that admit content, repair equal-content ACKs, cancel requests, Stop, repair cancel fences or settle empty transports without diagnostics are not rewritten as diagnostic transactions. In particular cancel and Stop never require a diagnostic owner or wait for B's lock. A diagnostic failure after an earlier ACTIVE activation preserves that activation and the existing held behavior; this is not a rollback of earlier saved work.

## Entry-point and outer-scope changes

1. `submit_cli`, `admit_saved`, `reject_response`, `get_brief`, `get_delivery` and `resume_request` invoke the private driver from outside a boundary. Locked capture/settle helpers are private; nested calls use those helpers, not a public driver while holding an outer boundary. `_resume_recovered`, `_repair_fulfilled_ack` and `_packet` participate through the same signal/continuation mechanism.
2. `mcp_bridge.chat_artifact_brief` currently holds one outer boundary around `get_parent` and `get_brief`. Replace that wrapper with `get_brief_context`. Parent-first validation and one shared A snapshot remain; B is genuinely unlocked. `chat_artifact_submit` and the HTTP transport currently call service entries without their own boundary; keep that property. No MCP tool name, schema, admission grant or response widening.
3. `recover_startup` currently wraps its entire task scan, retained-result scan and per-item public-service calls in one boundary. Replace this with an initial bounded task-id snapshot, retained-launch/outbox inventory outside the boundary, and fresh per-item capture/settlement boundaries. Each item re-reads its row/queue/result before choosing a branch. Preserve limit 1..100, dispatch de-duplication, duplicate retained authority refusal, existing counts/reasons, prepared/queued queue-repair-only selection, and final fresh guarded resume_pending marks for omitted items. Captured rows from the initial scan never authorize later effects. Work arriving after selection waits for a later pass; a selected id whose state changes uses the C table. No whole-pass serializability is claimed after this intentional change.
4. Startup may call public resume/admit drivers only without an outer boundary. Its direct diagnostic terminal-result branch uses the same driver. Existing per-item catch order and held mapping remain, with `_DiagnosticRequired` caught before them. No silent private signal escape into the worker's broad catches.

Proposed edit scope after review: artifact_service.py (private driver, capture/settlement helpers and public orchestration), artifact_store.py (memory-only attachment capture and nonblocking sticky marker), mcp_bridge.py (combined brief-context service call), the two authorized root test files, the existing measurement tool and contract/status receipts. Artifact worker/transport outcomes remain pinned through the existing service errors; no new worker capability, wire code, public DTO or worker retry loop. Any additional source edit required by an actual caller trace returns to review rather than silently widening this list.

## Reads and lock order

Source search at 7fe71f7 found no production caller of `ArtifactStore.diagnostics()` or `request_diagnostics()` outside their store definitions/delegation. The earlier structural timing harness deliberately invoked the report inside a shared boundary; that is a harness scope, not a hidden production call site. D4 replaces it with an outside-boundary report plus a real concurrent peer boundary user. Future reader/operator packages must call these report methods outside the boundary too.

`diagnostics()` may briefly use the authoring RLock for its authoring-object snapshot/inventory as currently specified; it releases that lock before diagnostic report IO. `request_diagnostics()` is ledger-only. Neither method may enter engine/catalog or hold authoring while taking the diagnostic owner lock. Slow diagnostic reads, validation, body inventory and fsync must not delay a peer cancel/Stop through any shared engine/catalog or authoring lock. This does not promise that unrelated authoring-index disk work is lock-free.

Allowed edges: engine -> catalog -> authoring for A/C, then all released; diagnostic -> diagnostic process -> body process for B. No engine -> diagnostic lock edge in capture, no diagnostic -> authoring or diagnostic -> engine edge. The nonblocking legacy event communicates a hold, never authority. No invocation-local intent, receipt or callback is stored on either owner or reused by another thread/call.

## Crash windows, idempotence and settlement faults

|Crash/failure point|Durable state and retry/recovery|
|---|---|
|After A, before B|Only pre-existing effects such as activation remain. No diagnostic-dependent terminal change or ACK. Same worker input can retry; cancel/Stop remain available. Startup follows the current live/transport/outbox rules, never infers an intent from memory.|
|Body put before metadata commit|Existing possible orphan body counts toward quota; no diagnostic receipt or C. Preserve current body-failure versus uncertain-metadata-commit rules.|
|B durable, before C|Diagnostic is retained, request may still be live. Retry reconstructs and revalidates the intent from trusted inputs, and deterministic detail ids deduplicate. A different intervening overflow key can increment the bounded summary again under the existing latest-key-only rule; this is not an exactly-once counter claim. No new journal or overflow-id history.|
|C terminal change saved, before fence|Existing partial state/fence window remains. No rollback or second version. Transport error is reported/held under existing rules, and Stop/cancel transport reconciliation stays independent of diagnostics. Do not invent automatic terminal-request resume or a new repair state machine.|
|C outbox disposition saved, before caller result|Replay sees disposition and uses current retained-result policy; it cannot admit that result. Durable diagnostic id is genuine.|

For sealed saved results, startup/resume/lost-ACK recovery can reconstruct the operation from the existing private brief, seal, outbox and committed version checks. A fulfilled row with matching content still repairs its lost ACK, without changing imported or fulfilled rows. For rejected raw API output, validation intentionally runs before `box.save` (R1); there may be no durable raw result after B. Startup must not infer a terminal invalid_response transition from diagnostic contents. The request remains live until an authenticated retry, cancel/Stop, or existing terminal-empty-transport settlement. This is an explicitly retained diagnostic-first crash window, not a new recovery authority.

B's process-lock timeouts remain 10 s + 10 s, plus unbounded OS IO/scheduling residual. FAULT writes return typed diagnostics unavailability and no C effect; already durable earlier effects remain. B has no hard wall-clock latency claim. C's authoring/fence/disposition failures keep their current fault classifications, with no success response manufactured after uncertainty.

## Informational tradeoff for Seth

Reducing retained detail/body budgets would preserve less rejected output and could reduce validation and inventory work, but it would change the agreed audit-retention behavior. The existing measurements establish costs at the current maximum only; they do not quantify a smaller-budget alternative. D4 keeps the current 8-per-group/256-group/1024-detail, 512 KiB body/8 MiB total/1024-object budgets and moves diagnostic IO outside the shared authority boundary. A budget reduction would be a separate decision for Seth, not an optimization chosen here.
