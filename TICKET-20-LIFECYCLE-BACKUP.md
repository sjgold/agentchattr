## Import-only request representation (P2, required decision)

The current store requires every imported request to own a version and requires managed API launch refs. The accepted local _audit stays unchanged, including storage-valid legacy CLI all-null refs with capabilities ['artifact-v1']; the service still requires nonnull managed refs for BOTH adapters. Local API null refs and every local capabilities=[] remain refused. That cannot represent an exported failed/pending attempt after stripping authority. Propose a narrow IMPORT-ONLY validator path, while local reserve/admission grammar remains unchanged:

- Preserve lineage/request/version/packet UUIDs as UIDs and the deterministic internal reference graph. A collision with ANY local member UID skips the entire lineage, including an identical re-import; never overwrite/merge/fork or append imported revisions onto a local head.
- Imported request state/reason is imported/imported, no pending slot. It may have version_id=null ONLY when it owned no exported version. A version still has exactly one matching imported request and contiguous sequence/parent/head checks stay strict. Fulfilled local requests still require a version. No local request may enter imported through set_attempt_state.
- Imported producer launch_attempt, launch_nonce and fingerprint are all null; capabilities=[] and no private brief is created. Use separate _audit_imported/_validate_imported paths selected ONLY by state=imported AND valid import_source, never shape alone. These shapes are accepted only through that dedicated import validator/commit. Preserve name, identity label, adapter, requested-model metadata, scope and original-channel data. No imported row can pass the live producer, claim, admission, queue eligibility or startup-resume gates.
- Store a strict import_source record ONLY on imported request rows: archive_id (1-64 characters, [A-Za-z0-9._-]), original_state (LIVE|TERMINAL), original_reason (STATE_REASONS). Stored version provenance stays unchanged; project import_source at read time. Keep the first recorded import origin on re-export; do not build an unbounded history chain. This preserves failed/pending history while the local state stays terminal. Local row shape and local audit validation remain unchanged. Imported rows are never pending/eligible or resumed/admitted, and set_attempt_state/commit_version refuse them. Imported-state without import_source refuses load.
- Packet bytes/original-channel/source-run/refs remain frozen; mutable outer channel alone is resolved/remapped. No reconstructing packets from local messages. No imported source reference is treated as a pointer authorizing local chat access.

Alternative considered: import only version-owning requests and drop unfulfilled attempts. Rejected as a proposal because it loses retained copied-source history and violates whole-lineage preservation. A separate parallel imported store would duplicate reader/lifecycle ownership. The accepted P2 import-only exception supersedes the earlier imported-own-version requirement solely for imported unversioned attempts; the payload review below still precedes any schema implementation.

### Portable metadata and members

All objects below are exact-key allowlists; unknown fields, duplicate keys, nonfinite numbers, malformed UTF-8, invalid ids and broken references refuse the artifact section. Existing512KiB Markdown,2MiB/1000-message packet, string grammar, canonical_utf8 and model-observation validators apply. Never obtain a member name from metadata text. Raw .md bytes and canonical packet bytes must match BOTH metadata byte_length and sha256. Packet structure/ordered refs/input revision/original_channel/source_run must agree with the corresponding request, as on local reads.

```text
artifacts/index.json = {version:1, lineages:[PortableLineage,...]}
PortableLineage = {lineage_id:32hex, channel:channel_name,
  updated_at:finite_timestamp, head_version_id:32hex|null,
  requests:[PortableRequest,...], versions:[PortableVersion,...]}
PortableRequest = {request_id:32hex, original_channel:channel_name, requester:text,
  producer:{name:text, identity_id:32hex, adapter:cli|openai-compatible,
            requested_model:text|null, requested_model_reason:text|null},
  source_run:existing_source_run|null, scope:existing_scope,
  instruction:text, format:text, expected_parent:existing_parent|null,
  created_at:finite_timestamp, updated_at:finite_timestamp,
  import_source:{archive_id:safe_token, original_state:LIVE|TERMINAL,
                 original_reason:STATE_REASONS}}
PortableVersion = {version_id:32hex, request_id:32hex, sequence:positive_int,
  parent_version_id:32hex|null, sha256:64hex, byte_length:positive_int,
  created_at:finite_timestamp, observation:existing_model_observation}
```

safe_token is1-64 ASCII characters matching [A-Za-z0-9._-]+. For local requests the exporter constructs import_source from the current export archive_id and source row state/reason; for already imported requests it preserves the stored FIRST origin. The current lineage channel is encoded once; every imported outer request/version channel is resolved from that value. Scope/source refs, expected_parent and source_run keep their existing exact schemas. Requests sort by request_id, versions by sequence, lineages by lineage_id. The graph includes every version/request/source packet of the frozen lineage, with no pending slot encoded.

Allowed members are artifacts/index.json, artifacts/objects/<version_id>.md and artifacts/packets/<packet_id>.json. packet_id is already in scope; attempt_id/dispatch_id/brief_id are DERIVED from request_ids(request_id), never exported fields. Portable producer has no launch_attempt/launch_nonce/fingerprint/capabilities. Portable index has no private brief/seal/owner, token, runtime path or arbitrary file-path fields. Human instruction/text can literally contain such words; the golden checks field projection and private sentinel values, not a substring ban on user text. Packets retain their existing source_document/attachment metadata as untrusted source data; these are not authority or filesystem paths for archive extraction.

New artifact-bearing manifest uses schema_version2 with the existing history metadata plus artifacts:{version:1,lineages:int,requests:int,versions:int,packets:int,markdown_bytes:int,source_bytes:int,copied_source_text:true}; existing counts gains artifacts=lineage_count. Zero lineages means no artifact section/members and the complete schema1 export is byte-identical to the captured pre-change writer under fixed UUID, clock and ZIP timestamps. An empty artifact owner does not emit schema2. An imported zero-version lineage with retained attempts DOES count as a nonempty artifact section. Schema1 containing artifact members refuses instead of silently ignoring them. Schema2 without an artifact section remains a valid history-only input.
