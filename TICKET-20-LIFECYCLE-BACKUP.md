## Lifecycle binding and preview

- Add a distinct authored_artifacts owner to ChannelService, supplied by the configured factory before catalog discovery. Add a late service getter for cancellation, since ArtifactService is constructed after ChannelService. Existing standalone component constructors may explicitly omit this owner; the configured factory always binds it. Missing/held configured owner closes artifact-sensitive management, never appears as an empty store.
- Extend data-only name discovery, catalog display and retained_view with owner key artifacts. Preserve the existing uploads owner. Metadata-only lists expose detached, nonce-free lineage/version/request references and per-owner errors; they never read Markdown or source packets under catalog display. A corrupt index reports held/count=null; a corrupt individual object stays per-object per M5 and does not hold unrelated metadata.
- Preview adds counts artifacts (lineages, including zero-version attempts), artifact_versions, artifact_requests (all attempts), artifact_source_bytes (sum of referenced packet byte lengths). The stable token includes lineage/head/request-state/version metadata, not just a count; append, request state or channel changes invalidate it. Counters disclose retained source copies separately from attachment references and message-with-attachment groups.
- One blocker kind artifact combines each live prepared/queued/active request and its retained queued/ACTIVE transport by deterministic dispatch id. It names request_id, dispatch_id, identity_id, request_state, transport_state and a fixed pending reason. Prepared with no transport still blocks. A terminal request whose transport remains dispatched/acknowledged/uncertain/cancelling still blocks. Other chat/review blockers keep their current shape and semantics.
- Archive, rename and delete refuse these blockers under the shared engine/catalog boundary. Reopen/read remain available as already ruled; inactive channels refuse new ordinary artifact writes. No lifecycle operation infers that an unobserved worker ended.
- Queued-only cancellation must cancel the request through ArtifactService.cancel_request before fencing its exact queued dispatch; raw queue-only cancellation must not strand a queued request. It skips no active/prepared blocker. The explicit operation remains separate from archive/delete. Recheck the preview under the boundary; partial fence failure reports cancelled request plus unconfirmed transport, preserves evidence, and retries only the fence. Do not report a channel mutation succeeded.

## Backup shape and authority boundary (P1)

Propose archive schema2 for new exports, so an older importer refuses rather than silently dropping artifact deliverables. The new importer accepts schema1 archives without any artifact section. Preserve existing four section behavior. Add optional keyword-only artifact_store to build_export/import_archive/_do_import/_configured_import and thread the actual store through both app call sites; avoid global store lookup. An artifact-bearing archive with no configured artifact owner refuses, never silently discards the section.

Proposed fixed artifact namespace: artifacts/index.json (portable metadata version1), artifacts/objects/<version_id>.md (exact binary UTF-8), artifacts/packets/<packet_id>.json (exact canonical packet content). Member names derive only from validated32hex ids and fixed prefixes. No extractall, source-controlled filesystem path, link traversal or fetching attachment URLs. Reject duplicate artifact ZIP names, unsafe/unknown artifact members, malformed UTF-8/duplicate/nonfinite JSON, invalid hashes, broken parent/version order and missing referenced objects. Attachment binaries remain excluded as in existing history backups; copied packet text and attachment references are included and disclosed.

Snapshot one lineage's metadata under its store lock, then validate/read its immutable objects outside the outer engine/catalog boundary. Concurrent later versions may be absent from this frozen export, but every included head/request/parent/object must agree with that same snapshot. No cross-lineage point-in-time claim. Fail loudly on held/corrupt referenced objects; no partial successful ZIP. Budget the exact encoded manifest and all members before returning; enforce <=50MiB uncompressed AND final ZIP <=50MiB, matching both current importer/upload bounds. Read import members with bounded readers and validate actual sizes/hashes as well as declared ZipInfo sizes.

Export lineages includes every request attempt and referenced source packet, even if no version was produced. Exclude private brief seal/owner records, launch snapshots, bearer/nonce/launch authority, outbox/ACK/disposition/invocation journals, quarantine bodies and orphan objects. Preserve authored bytes, source refs, producer name/identity label, requested/recorded model labels and absent-model reasons, source run/input revision and timestamps. Imported model metadata is explicitly archive-recorded provenance, never a current locally verified observation.

## Import-only request representation (P2, required decision)

The current store requires every imported request to own a version and requires managed API launch refs. That cannot represent an exported failed/pending attempt after stripping authority. Propose a narrow IMPORT-ONLY validator path, while local reserve/admission grammar remains unchanged:

- Preserve lineage/request/version/packet UUIDs as UIDs and the deterministic internal reference graph. A collision with ANY local member UID skips the entire lineage, including an identical re-import; never overwrite/merge/fork or append imported revisions onto a local head.
- Imported request state/reason is imported/imported, no pending slot. It may have version_id=null ONLY when it owned no exported version. A version still has exactly one matching imported request and contiguous sequence/parent/head checks stay strict. Fulfilled local requests still require a version. No local request may enter imported through set_attempt_state.
- Imported producer launch_attempt, launch_nonce and fingerprint are all null; capabilities=[] and no private brief is created. These shapes are accepted ONLY for imported rows through the dedicated import validator/commit. Preserve name, identity label, adapter, requested-model metadata, scope and original-channel data. No imported row can pass the live producer, claim, admission, queue eligibility or startup-resume gates.
- Add a strict import_source metadata record ONLY to imported request rows (and projected version provenance): archive_id, original_state, original_reason. Keep the first recorded import origin on re-export; do not build an unbounded history chain. This preserves failed/pending history while the local state stays terminal. Local row shape and local audit validation remain unchanged.
- Packet bytes/original-channel/source-run/refs remain frozen; mutable outer channel alone is resolved/remapped. No reconstructing packets from local messages. No imported source reference is treated as a pointer authorizing local chat access.

Alternative considered: import only version-owning requests and drop unfulfilled attempts. Rejected as a proposal because it loses retained copied-source history and violates whole-lineage preservation. A separate parallel imported store would duplicate reader/lifecycle ownership. P2 needs explicit review before expanding the schema, including the earlier imported-own-version rule; no schema change is being smuggled into a test brief.

## Whole-lineage commit and reports (P3)

Propose pure artifact_archive.py codecs/validation and dedicated ArtifactStore export-metadata/read-object/import-lineage methods; freeze exact payloads after this contract review. Import validates a whole lineage and all object caps outside the policy boundary. Under one short engine/catalog boundary, resolve that lineage's channel through existing resolve_import_channel, recheck collisions and atomically commit all lineage/request/version references with pending=null. Objects stage first by immutable deterministic ids; index commit last. A fault leaves no partial referenced lineage; staged orphan objects are reported, never auto-deleted. Exact repeated staged objects may be reused; differing bytes never overwrite.

Release the boundary between lineages. A pending repair at import start refuses409. A repair/inactive/retired/reserved name appearing mid-import uses the existing remap policy for subsequent lineages; report channel_repair_pending/channel_retired etc exactly, without rewriting frozen source. Existing partial import semantics continue, with per-artifact-section counts for created_lineages/versions/requests, duplicate/conflict/skipped lineages and exact reasons. On later storage failure, report only prior committed lineages as created and mark the import partial/failed; staged objects are not created deliverables. No dispatch, registry update, engine run, provider call, timer or admission callback occurs during import.

Counts of copied source bytes describe included packet objects, not attachment binary sizes. Valid imported versions remain immutable/readable on inactive/deleted channels. Reassignment or new authoring is a NEW explicit local request after capability/public-route gates, not an import side effect.
