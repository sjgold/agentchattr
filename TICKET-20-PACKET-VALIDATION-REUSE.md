# Ticket 20 A1: one packet validation per service invocation

Status: PROPOSED CONTRACT, docs only. Reviewer direction accepted A1 before D4 reds; exact mechanism, reds and source still require review. No optimization has been implemented or measured. This is behavior-preserving invocation-local reuse, not R3 reference compaction, authoring capacity policy or a persistent cache.

## Purpose and current evidence

At 3c04b0d the design-only combined parent/brief call measured median 0.238026 s, maximum 0.264433 s over ten max-source fixtures (2 MiB packet, 1000 refs, 512 KiB parent and 128 small prior requests). It reads/validates that packet through get_parent, service _packet and the queued-to-active state transition. Each store._packet currently parses, computes message refs/canonical encoding and re-encodes for byte equality. [All design measurements and limitations](TICKET-20-DIAGNOSTIC-PHASE-DESIGN.md) remain evidence, not an A1 or D4 pass.

A1 removes duplicate content validation of the exact same bytes within one service call chain. Reads remain at their current points, as do fresh owner/index/request/authority checks. The target after A1 is <=0.216 s for combined A and the other caller classes; no timing improvement is claimed in this document.

## Boundary and margin clarification

The hard cap remains 0.270 s for every measured shared-boundary hold. The <=0.216 s clearance margin applies to holds D4 adds or changes, including its new per-caller A and C settlement, and the final gate of work D4 introduces. A pre-existing independently cleared authoring path below 0.270 s is not retroactively failed solely for being above 0.216 s; it must be reported to Seth as an authoring-capacity fact. No rounding or exclusion changes any historical result.

Combined parent/brief's current ~0.24–0.26 s max-source hold on this machine is such a reported fact. A1 targets margin there. If it cannot reach 0.216 s, retain the result as a capacity limit feeding the R3 contract and later finite-capacity disclosure; do not block D4 solely on that pre-existing path. D4's newly added/changed holds must still meet the margin. An existing path exceeding 0.270 s remains a hard miss. No store quota, lower retention budget or R4 design is chosen by this clarification.

## Reuse points and unchanged checks

|Current site|A1 behavior|
|---|---|
|ArtifactService.get_parent -> store.get_packet -> store._packet|First successful full packet validation can create private evidence for the exact bounded raw bytes. Existing parent version read/hash/length/sequence validation remains separate and unchanged.|
|ArtifactService._packet -> store.get_packet -> store._packet|Read the packet again exactly where it does today. Exact same raw bytes may reuse successful content validation; unavailable/different bytes take the existing error/full-validation path. Service diagnostic behavior is unchanged by A1.|
|ArtifactStore.set_attempt_state -> self._packet for queued/active transitions|Same mandatory read, fresh request/index/state/lineage checks, current matching-audit checks and full authoring _persist validation. Only repeated parsing/_packet_scope/_canonical-byte comparison of already validated identical bytes can reuse evidence.|
|Other _packet calls reached inside the same selected service invocation (e.g. validate_enqueue on a resume)|May consume the same private evidence after a fresh bounded raw read and current-audit checks. No new skip for coordinator/admission/claim callers outside that invocation.|
|Worker _packet_scope, archive codec/preflight, store.put_packet, import staging/export outside a service call|Unchanged full validation. No evidence is inferred from a caller-built packet, public dict, object stat, archive checksum or persisted metadata.|

The successful content result consists of the parsed packet and its computed scope after semantic grammar, message uniqueness/ref hashes, input/source-run agreement, size, canonical encoding and exact canonical/raw-byte equality have all passed. The loop checking every current request referring to that packet against scope/original_channel/source_run executes on EVERY read, outside the reusable content step. It may refuse after a content hit if the authoring index changed. Register newly validated content as evidence only after that first read's current-audit loop also succeeds; a failed read creates no new reusable entry. _check_index, owned-path safety, _read_object size/read failures, object-error recording/clearing, request matching, state transitions, lock order, fsync and immutable writer behavior are unchanged.

## Private mechanism and evidence type

Proposed implementation stays in artifact_store.py, with an ArtifactService entry-scope adapter. No new module, public argument, persisted field, owner attribute cache or on-disk object is added.

|Name/signature|Frozen behavior|
|---|---|
|`_packet_validation_invocation(owner)`|Private synchronous context manager creating one new `_PacketValidationInvocation` and setting a private ContextVar with a finally reset. It is called by a top-level selected service/MCP entry, never by a model or generic store read. A new top-level invocation always starts empty, even if another context value exists.|
|`_PacketValidationInvocation`|Private invocation-local record: owner object identity, resolved root/path identity captured from that owner, originating threading.get_ident(), fresh object() token, bounded evidence map. It is never assigned to the owner, queue, envelope, diagnostic intent, body or ledger. Scope ends on success, exception, diagnostic failure or generator close; do not hand this synchronous context across tasks.|
|`_ValidatedPacketBytes`|Private frozen evidence: packet_id, raw immutable bytes, SHA-256, byte_length, and detached content-validation result. It is created only by the successful full content-validation helper and registered with the current invocation's private token. No constructor/dict/attribute supplied by a public caller is accepted as proof.|
|`_read_validated_packet_content(packet_id, raw)`|Private store helper. With no usable invocation evidence, run the full existing content checks. With evidence, require exact owner/root identity, thread id and active token, packet_id, len(raw), SHA-256(raw) and raw-byte equality. Only then copy the validated content/scope result. Any absent/forged/expired/mutated/mismatched evidence falls back to FULL validation, not a skip and not an evidence-specific rejection. Existing packet errors remain the authority on bad bytes.|
|`ArtifactService._packet_invocation(step)`|Private entry adapter: start a fresh store invocation scope around the complete synchronous selected operation, including its existing authority boundary. Only explicit internal nested helpers participate in that scope; unrelated public calls get a fresh scope. No caller parameter enables reuse. D4 later composes its diagnostic driver inside this scope; evidence contains no request-state/producer/queue authority.|

ContextVar alone does not establish thread ownership: compare threading.get_ident() on every evidence lookup, including when a copied context is deliberately entered on another thread. Another independent request on the same thread begins a fresh scope/token. Nested selected top-level calls isolate and restore their enclosing scope through ContextVar tokens rather than leaking evidence. A plain store method called after the service returns, in another thread, during startup scanning outside a selected service item or without the private adapter always fully validates.

The map is bounded to at most two packet results and at most 2 * MAX_PACKET_BYTES raw bytes per invocation (without counting their parsed copies). The common chain uses one. A third distinct key or an oversize aggregate simply bypasses evidence storage and validates normally; do not evict/reassign evidence in a way that admits an unvalidated packet. No timing, error or acceptance depends on a cache entry being present. This memory-only implementation bound changes no packet, request, diagnostic or authoring admission limit.

Cached content/scope results use a recursively immutable representation (tagged tuples of key/value pairs or list elements, immutable scalars and raw bytes), not mutable dict/list trees. Reconstruct a detached packet/scope for every hit, just as get_packet already returns a detached packet; mutation by a caller cannot alter evidence for a later read. The invocation registry records an immutable binding tuple for each successful factory-issued evidence object: exact evidence identity, token identity, owner/thread/id/hash/length/raw and immutable-result identity. An arbitrary `_ValidatedPacketBytes` lookalike, replaced registry entry without its factory binding, stale token or replaced evidence field cannot become a hit. No callable accepts external registrations. If private state integrity cannot be established, run full validation. Tests mutate/forge evidence without also replacing the validator/factory themselves. No public security guarantee relies on Python private naming; the proof is the absence of a public evidence ingestion path and the validation factory/lookup invariants, tested adversarially.

Error-only results are never cached. A failure records the same scoped object observation and raises the same ArtifactUnavailable as today. Successful hits still clear that same packet's prior observation at the existing point. A hash collision is insufficient for reuse because exact raw bytes must also compare equal. A same-size/mtime rewrite is caught by the fresh read, not a stat fingerprint. A packet file removed/replaced with a symlink or made unreadable between calls still executes the existing owned-path/read checks and refuses exactly as before.

## Exact entry composition, before D4

The combined MCP tool needs one invocation scope covering parent and brief. A1 introduces the proposed internal ArtifactService.get_brief_context entry as a behavior-preserving combined operation with its CURRENT one shared boundary, parent-first validation, then brief read/activation. It calls private locked parent/brief helpers rather than independently scoped public entries. The MCP tool calls that combined entry and, for A1 only, retains its existing outer boundary through JSON serialization/limit checking. The combined entry's reentrant scope does not change that outer hold. A1's evidence lives only through the combined service call; no packet validation happens during the later serialization. Removing the MCP outer boundary and relocating serialization/diagnostic IO is D4 work, not part of A1. A refused parent still prevents activation and the existing MCP tool DTO/error behavior stays the same.

Other selected service entries get one fresh scope each: get_parent and get_brief when called independently, get_delivery, submit_cli, admit_saved, reject_response, resume_request and prepare_request. Their nested private _packet/state/enqueue calls may reuse the same exact validated content. recover_startup's existing whole-pass scope is NOT one packet invocation: each selected per-request operation receives a fresh scope, so the recovery pass cannot accumulate a cross-request cache. Startup helpers that do not use an entry adapter remain full-validation callers. No whole-pass cache or owner-wide evidence.

Store._packet remains the common read/check path. Refactor only its existing content parse/scope/canonical check into the private validation helper; retain current-audit loop and exception/object-observation handling at the outer path. Before implementing, tests trace all callers listed above and prove no non-selected worker/codec/import/export caller silently acquires invocation evidence.

## Reds and equivalence tests, after exact contract review

One bounded root A1 test file may be proposed for approval; no helper is assigned. Existing R1/R2 tests remain intact. Test names and required assertions:

|Test|Proof|
|---|---|
|`test_combined_brief_reads_three_times_but_validates_content_once`|Instrument actual store bounded reads/content helper in the real managed fixture. Three current reads, one full successful content validation, unchanged returned bytes/parent/state/claim and detachment. On old product, repeated validation is a behavioral red (count semantic validation via _packet_scope, not a missing-helper AttributeError).|
|`test_changed_packet_bytes_force_full_validation_with_same_size_and_mtime`|Rewrite with valid different bytes between current read points; preserve stat if desired. Full validation runs again and current audit mismatch refuses. Also a different packet id/root/owner forces validation. No stale result or success.|
|`test_packet_evidence_is_not_reused_across_calls_or_threads`|Repeat service call, plain store read and concurrent/copy-context second thread each validate fully. Same-thread nested top-level operation gets a different token and restores prior scope safely. Exceptions clear scope in finally.|
|`test_forged_or_mutated_packet_evidence_falls_back_to_full_validation`|Inject lookalike/stale-token/wrong-owner/wrong-hash/wrong-length/wrong-raw and altered parsed-result evidence. Observe full validator calls and the same refusal for invalid bytes, never a false hit. Test map-bound overflow is transparent.|
|`test_packet_validation_reuse_matches_uncached_error_and_observation_outcomes`|Differential cached-scope vs no-scope on corrupt JSON, noncanonical JSON, oversize raw, same-size changed bytes, bad message ref/source-run/scope and a current-audit hash mismatch. Same exception family/text, object observations and zero version/state effects. Healthy empty/max/Unicode/CRLF packets yield identical detached results; R1 semantic bounds remain.|
|`test_invocation_hits_recheck_current_audit_and_owned_path_every_time`|Change index binding, remove packet, substitute unsafe path or raise read error after initial success. Fresh caller checks refuse despite content evidence, no bypass of _check_index, path safety, state validation or current scope comparison.|

The reviewer asked for observed reds before source. Evidence-forgery/helper API tests may initially be infrastructure errors, labeled separately; pair them with old-product behavioral repeated-validation/differential guards and later mutation checks so a missing helper is not the claimed proof. Never disable raw reads or full authoring _persist to obtain a timing improvement.
