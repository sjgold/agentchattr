# Ticket 20 A1: one packet validation per service invocation

Status: PROPOSED CONTRACT, docs only. Reviewer direction accepted A1 before D4 reds; exact mechanism, reds and source still require review. No optimization has been implemented or measured. This is behavior-preserving invocation-local reuse, not R3 reference compaction, authoring capacity policy or a persistent cache.

## Purpose and current evidence

At 3c04b0d the design-only combined parent/brief service work (including a harness guard-copy/hash, excluding MCP response serialization) measured median 0.238026 s, maximum 0.264433 s over ten max-source fixtures (2 MiB packet, 1000 refs, 512 KiB parent and 128 small prior requests). It reads/validates that packet through get_parent, service _packet and the queued-to-active state transition. Each store._packet currently parses, computes message refs/canonical encoding and re-encodes for byte equality. [All design measurements and limitations](TICKET-20-DIAGNOSTIC-PHASE-DESIGN.md) remain evidence, not an A1 or D4 pass.

A1 removes duplicate content validation of the exact same bytes within one service call chain. Reads remain at their current points, as do fresh owner/index/request/authority checks. The target after A1 is <=0.216 s for combined A and the other caller classes; no timing improvement is claimed in this document.

## Boundary and margin clarification

The hard cap remains 0.270 s for every measured shared-boundary hold. The <=0.216 s clearance margin applies to holds D4 adds or changes, including its new per-caller A and C settlement, and the final gate of work D4 introduces. A pre-existing independently cleared authoring path below 0.270 s is not retroactively failed solely for being above 0.216 s; it must be reported to Seth as an authoring-capacity fact. No rounding or exclusion changes any historical result.

Combined parent/brief's current ~0.24–0.26 s max-source hold on this machine is such a reported fact. A1 targets margin there. If it cannot reach 0.216 s, retain the result as a capacity limit feeding the R3 contract and later finite-capacity disclosure; do not block D4 solely on that pre-existing path. D4's newly added/changed holds must still meet the margin. An existing path exceeding 0.270 s remains a hard miss. No store quota, lower retention budget or R4 design is chosen by this clarification.

## Private mechanism and evidence type

Proposed implementation stays in artifact_store.py, with an ArtifactService entry-scope adapter. No new module, public argument, persisted field, owner attribute cache or on-disk object is added.

|Name/signature|Frozen behavior|
|---|---|
|`_packet_validation_invocation(owner)`|Private synchronous context manager creating one new `_PacketValidationInvocation` and setting a private ContextVar with a finally reset. It is called by a top-level selected service/MCP entry, never by a model or generic store read. A new top-level invocation always starts empty, even if another context value exists.|
|`_PacketValidationInvocation`|Private invocation-local record: owner object identity, resolved root/path identity captured from that owner, originating threading.get_ident(), fresh object() token, bounded evidence map. It is never assigned to the owner, queue, envelope, diagnostic intent, body or ledger. The context manager yields no evidence object to callers. Scope ends on success, exception, diagnostic failure or generator close; do not hand this synchronous context across tasks.|
|`_ValidatedPacketBytes`|Private frozen evidence: packet_id, exact raw immutable packet bytes and immutable canonical bytes of the FIRST successfully computed scope, created together by one full validation, plus owner/root/thread/token binding and raw hash/length. No parsed packet, immutable tuple tree, deepcopy or cached audit/authority state. The invocation factory registers the issued object and exact raw/scope pair; mismatched/forged pairs fall back to full validation.|
|`_read_validated_packet_content(packet_id, raw, *, need_packet=True)`|Private store helper wrapping ONLY the current _packet content block, never _packet_scope. With no usable evidence, run the full existing content checks. On a hit require owner/root/thread/token, packet_id, raw hash/length and EXACT raw equality plus the factory-issued matching scope bytes. json.loads(scope_bytes) returns a fresh computed scope; json.loads(raw) returns a fresh packet when need_packet is true. No content walk/canonical compare on a hit. Any absent/forged/expired/mutated/mismatched evidence falls back to FULL validation. It never uses audit.scope as the computed side of the audit comparison.|
|`ArtifactService._packet_invocation(step)`|Private entry adapter: start a fresh store invocation scope around the complete synchronous selected operation, including its existing authority boundary. Only explicit internal nested helpers participate in that scope; unrelated public calls get a fresh scope. No caller parameter enables reuse. D4 later composes its diagnostic driver inside this scope; evidence contains no request-state/producer/queue authority.|

ContextVar alone does not establish thread ownership: compare threading.get_ident() on every evidence lookup, including when a copied context is deliberately entered on another thread. Another independent request on the same thread begins a fresh scope/token. Nested selected top-level calls isolate and restore their enclosing scope through ContextVar tokens rather than leaking evidence. A plain store method called after the service returns, in another thread, during startup scanning outside a selected service item or without the private adapter always fully validates.

The map is bounded to at most two entries and at most 2 * MAX_PACKET_BYTES raw packet bytes per invocation, plus the matching immutable scope encodings (roughly150KB scope plus2MiB raw per max-source entry in the measured shape). No cached parsed copies. The common chain uses one. A third distinct key or an oversize aggregate simply bypasses evidence storage and validates normally; do not evict/reassign evidence in a way that admits an unvalidated packet. No timing, error or acceptance depends on a cache entry being present. This memory-only implementation bound changes no packet, request, diagnostic or authoring admission limit.

The matching raw/scope pair is stored only as immutable bytes. The invocation registry retains the exact issued evidence identity and its original immutable pair/bindings; replacing a field or a registry entry without the issuance binding causes fallback. No unchecked scope-ingestion method exists. json.loads creates fresh packet and computed-scope objects on every hit. Mutating either returned dict/list cannot change a later read or the immutable bytes. The store get_packet path returns that fresh parsed packet directly, without the old additional2MiB deepcopy on a hit; first/miss results are fresh parses too, so no owner-owned object is exposed. _packet may take private keyword _need_packet=False only at set_attempt_state:1316 and _commit_new:1363, whose existing callers discard the packet. It still validates fully on a miss and performs the current-audit loop. get_packet/_reserve_new/export keep the packet result. This flag changes materialization only, never validation/authority.

Root/path identity means the exact ArtifactStore object (two instances on the same directory are different), its resolved configured root and resolved authoring-index path captured at scope entry and compared on use; owned-path safety still executes at each real read. Detached means no mutable descendant is shared with evidence, the owner or a previous returned value. A selected public entry is an invocation adapter entry, whether called directly or from another public entry. Nested selected public entries ALWAYS get a fresh empty scope/token and restore the outer scope in finally, including on exception. Private locked helpers in the same public call join its scope. Evidence may survive a boundary release/reacquire only while that SAME invocation scope remains active; neither release nor re-entry makes it transferable to another invocation. recover_startup's calls to resume_request/admit_saved therefore each have fresh scopes, not one recovery-wide cache.

Error-only results are never cached. Failures caught by the existing _packet exception tuple record the same scoped object observation and raise the same ArtifactUnavailable. Uncaught errors preserve their existing behavior; in particular json.loads RecursionError escapes without a new object observation, as specified below. Successful hits still clear that same packet's prior observation at the existing point. A hash collision is insufficient for reuse because exact raw bytes must also compare equal. A same-size/mtime rewrite is caught by the fresh read, not a stat fingerprint. A packet file removed/replaced with a symlink or made unreadable between calls still executes the existing owned-path/read checks and refuses exactly as before.

## Exact entry composition, before D4

The combined MCP tool needs one invocation scope covering parent and brief. A1 introduces the proposed internal ArtifactService.get_brief_context entry as a behavior-preserving combined operation with its CURRENT one shared boundary, parent-first validation, then brief read/activation. It calls private locked parent/brief helpers rather than independently scoped public entries. The MCP tool calls that combined entry and, for A1 only, retains its existing outer boundary through JSON serialization/limit checking. The combined entry's reentrant scope does not change that outer hold. A1's evidence lives only through the combined service call; no packet validation happens during the later serialization. Removing the MCP outer boundary and relocating serialization/diagnostic IO is D4 work, not part of A1. A refused parent still prevents activation and the existing MCP tool DTO/error behavior stays the same.

Other selected service entries get one fresh scope each: get_parent and get_brief when called independently, get_delivery, submit_cli, admit_saved, reject_response, resume_request and prepare_request. Their nested private _packet/state/enqueue calls may reuse the same exact validated content. recover_startup's existing whole-pass scope is NOT one packet invocation: each selected per-request operation receives a fresh scope, so the recovery pass cannot accumulate a cross-request cache. Startup helpers that do not use an entry adapter remain full-validation callers. No whole-pass cache or owner-wide evidence.

Store._packet remains the common read/check path. Refactor only its existing content parse/scope/canonical check into the private validation helper; retain current-audit loop and exception/object-observation handling at the outer path. Before implementing, tests trace all callers listed above and prove no non-selected worker/codec/import/export caller silently acquires invocation evidence.
