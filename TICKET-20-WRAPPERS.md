## Scope and source findings

Add a purpose branch to the existing persistent CLI/API workers and the smallest authenticated server bridge needed to exercise it. Reuse the existing queue, managed launch, immutable brief, sealed artifact outbox, cancellation and admission. No second worker/run/phase engine, provider dependency, ordinary-chat artifact inference, operator request picker, reader or archive integration in this package. Public request creation remains unavailable until the later routes/lifecycle package and its K6 snapshot/timing checks pass.

Verified source at52d52f1: wrapper._queue_watcher.prompt chooses review solely by review_brief_id and otherwise appends ordinary chat_send instructions; CliConsumer tracks injection only in memory and reports cancelling as unsupported. wrapper_api.handle_trigger reads chat before its frozen branch; its loop forwards only the existing review/chat keys. call_model returns only content, although run_completion returns confirmed_model; the receipt is shared seat state. complete_review_turn returns status=saved for a prior result, which the review wrapper currently treats as local_delivery_failure. QueueClient generates a new consumer per instance, and the ledger refuses a different consumer reclaiming active work. API invocation_evidence.begin already makes a durable per-dispatch mkdir fence before any provider subprocess. Do not change those legacy review semantics in this package.

## Producer transport and MCP surface

Proposed NEW artifact_transport.py owns an explicitly bound FastAPI router, body limits and service error projection. It is the agent-only bridge; the operator library/request/preview/download routes remain a separate package. Every route requires a current authenticated seat bearer, not an operator token, cookie or caller-supplied identity. Exact validated hex path ids, singleton route parameters, no arbitrary URL/path/channel parameters, no-store responses including delivery. Authentication occurs before reads or mutations. Map access403, malformed400, conflict409 and held503, catching conflicts before ValueError; errors never echo exceptions, paths, body text or secret material. Actual middleware tests reject an operator token/cookie on EVERY artifact agent route; later operator routes reject seat bearers symmetrically. A captured-log/error-body redaction assertion must show neither seal secret nor bearer/nonce, including malformed/private-delivery failures. Only the authorized successful internal API delivery response contains its private authority.

| Proposed route | Exact body and service operation |
| --- | --- |
| GET /api/artifact-briefs/{brief_id} | No body/query; get_brief(brief_id,instance), projected brief plus exact packet, no nonce/seal. |
| GET /api/artifact-briefs/{brief_id}/delivery | No body/query; get_delivery, managed API only. Private authority goes to the trusted wrapper, never its model prompt. CLI tokens refuse. |
| GET /api/artifact-briefs/{brief_id}/parent | No body/query; proposed claimed get_parent below. Reads only the immutable expected parent of this assigned request, not an arbitrary artifact/version id. |
| POST /api/artifact-results | Exactly the existing {payload,seal} record; admit_saved(record,instance). Returns the exact ACK or QuarantineResult, never ordinary chat. |
| POST /api/artifact-briefs/{brief_id}/reject | Proposed rejection report below; managed API only, full claimed/live gate, terminal invalid_response settlement. |

Request readers reject malformed UTF-8, duplicate keys, non-finite JSON, extras and oversize before parsing/service mutation. POST artifact-results uses MAX_RESULT_RECORD_BYTES. Combined brief+packet+parent context has a fixed serialized cap of6*(MAX_PACKET_BYTES+MAX_ARTIFACT_BYTES)+MAX_BRIEF_RECORD_BYTES+16384, currently15,974,400 bytes, covering worst-case JSON escaping of2MiB packet plus512KiB parent and bounded brief/metadata. Enforce that bound before sending a CLI tool response; no partial/truncated source or parent. A known transport/client refusal returns a fixed context-unavailable error where a response is still possible, with no generation or fallback. The app cannot infer an undocumented client context window or detect silent client-side truncation; such a client is unsupported for that scope until the operator selects a smaller scope and acceptance proves it. Reject-report transport uses6*MAX_RESULT_RECORD_BYTES+32768 bytes for bounded escaped diagnostic text; this is distinct from the service's smaller encoded-content cap.

MCP adds exactly chat_artifact_brief(brief_id:str,ctx=None) and chat_artifact_submit(brief_id:str,markdown:str,ctx=None), registered in _ALL_TOOLS. Reuse _authenticated_instance, then service.get_brief plus the proposed assigned get_parent, or submit_cli. The brief tool returns {brief,packet,parent}; parent is null for a new lineage. The model supplies ONLY its assigned brief id and authored Markdown. It cannot set dispatch/attempt/parent/scope, producer/model observation, seal, request id, transport state, recovery flag or source metadata. Submission is CLI-only. The result is JSON containing the existing ACK/QuarantineResult or a fixed safe error projection. Retryable CLI validation exposes code=invalid_content, diagnostic_id and received_truncated and leaves ACTIVE; it does not become an admitted result. Terminal/state/claim refusals tell the agent to stop, with no chat fallback. Instructions state the512KiB UTF-8 cap and preserve exact CRLF/Unicode; no1000-character summary limit applies.

chat_queue_release remains separate transport settlement, never submission. An invalid retryable tool call must not release the dispatch automatically. Successful submission receives ACK first, then the agent calls chat_queue_release with the injected dispatch id. Premature release refuses any later submission immediately because the claim is no longer active; failed/delivery_unconfirmed request settlement occurs only at explicit resume or the one startup pass, not synchronously in the existing release tool. Existing ordinary chat tools remain available but cannot complete artifact requests. MCP global instructions and purpose-specific prompts explicitly prioritize the assigned artifact contract over the existing ordinary-chat response instruction. Tool registration exposes both names to every MCP seat, so protection is the authenticated claim/seat/capability gate, not hiding names. Add named test_artifact_tools_are_registered_and_all_legacy_tools_remain, update any existing tool-list enumeration explicitly and retain every legacy tool; include the real list_tools path used by test_mcp_proxy rather than relying on a hand-maintained count.

## CLI branch and active transport

cli_worker passes its owned runtime path and verified birth/snapshot capability declaration to _queue_watcher through new optional keyword arguments; unmanaged callers retain defaults that cannot execute artifact work. wrapper.py checks purpose BEFORE review_brief_id. Absent purpose follows the byte-compatible legacy path. Unknown purpose or missing managed capability refuses, with no injection or chat fallback. The artifact prompt contains only validated owned ids, tool names, source-is-data instructions and explicit submit-then-release ordering. It does not append chat_send, job routing or mutable recent-chat/rules/source text.

Before a first artifact injection, a configured artifact_worker preflight validates envelope fields against the live claimed server brief and immutable runtime. The source packet is not embedded in the injected line; the agent retrieves it through its assigned MCP tool. CliConsumer gains an optional artifact preflight callback while its default ordinary/review behavior remains unchanged. A definitive preflight403/409 is a refusal before injection: release failed with a fixed category, never uncertain keystrokes or model work. A network/503 failure retains ownership for explicit repair and never injects. Unknown/malformed purpose cannot execute the callback as ordinary work.

Inspect ArtifactOutbox in that exact runtime BEFORE requesting a generation brief. If a result already exists, redeliver the same record through POST artifact-results using deliver_saved_artifact, including ACK-only replay for fulfilled requests. Successful redelivery releases transport normally; a terminal QuarantineResult records its disposition and ends work without generation. A diagnostic-only conflict holds the saved record for operator action, with no terminal disposition. A local ACK alone does not permit rewriting content. No review status=saved shortcut is used for artifacts.

Preserve single injection within the live CliConsumer and the ledger's original consumer ownership. A new worker/watcher has a new consumer and cannot inherit or guess the old claim. An acknowledged/uncertain artifact seen without matching in-memory injection evidence must not be injected again when no saved result exists; retain uncertainty for the existing exact-exit/operator path. This proposal adds no durable CLI injection journal or consumer-id persistence. Two mandatory concrete tests: (1) the SAME watcher process sees its same acknowledged/uncertain artifact again with no saved result and injects exactly once total, including injection-before-ACK uncertainty; (2) a RESTARTED watcher gets a new consumer, its claim of that active record raises QueueBusy and it never injects. If either fails or another supported restart can replay injection, stop before implementation continues and return a bounded journal proposal for review.

## API branch and trusted model observation

wrapper_api's entry extraction forwards purpose and all four artifact_* keys. Branch on purpose BEFORE frozen/review detection, before read_messages and before ordinary prompt formatting. Unknown purpose fails closed, never generate/read mutable chat. The branch requires a managed launch with matching enabled birth/snapshot manifest. Header, private delivery authority and packet must agree with the claimed envelope and owned runtime before provider work.

Proposed additive call_model(messages,dispatch_id,*,include_observation=False): the default remains the same text return for every existing review/chat caller. Only the artifact branch asks for a detached per-call {content,confirmed_model} from that exact run_completion return. It never reads receipt.value.confirmed_model as evidence. Known returned model -> observation confirmation_reason=api_response; absent -> null/provider_did_not_report_model. Provider/model strings in generated JSON are rejected as unknown fields. The existing worker and one-active-record queue remain strictly sequential per seat: no overlapping dispatches on ONE seat. Observation-isolation tests use sequential calls on one seat and overlapping calls on TWO independent seats/helpers, with explicit controlled observations; they do not claim concurrent work on one seat. Existing review tests, payloads and model-call behavior remain unchanged.

artifact_worker constructs model messages from the accepted frozen instruction, exact ordered packet/input and expected-parent revision context supplied by the application. Source is explicitly untrusted data. Include a strict response contract of exactly {"kind":"artifact","markdown":"..."}, with no fences/extras. Do not strip, normalize, remove a self-prefix or publish the raw response. Parse through artifact_protocol.parse_response, bind trusted observation and exact frozen header/consumer_id, save the sealed result atomically BEFORE submit, then deliver_saved_artifact. Secret, launch nonce and consumer_id never enter model messages, receipt text or logs.

Saved-result lookup precedes private delivery fetch or generation, so a fulfilled/terminal request can ACK-replay or refuse without regeneration. A missing result after an existing invocation intent means uncertainty and explicit operator action, never another completion. Retain invocation_evidence.begin's exact per-dispatch one-invocation fence and cleanup; do not weaken its exist_ok=False or share it with another dispatch. Status receipts say saved/admitted/held generically; their model display is not admission authority.

### Approved rejection-report amendment

Bounded invalid provider text must reach the existing terminal reject_response path without an unbounded transport. Approved exact report is {content:string,received_truncated:false} when its UTF-8/surrogatepass size is within MAX_RESULT_RECORD_BYTES, or {content:null,received_truncated:true} when larger. The latter reports no body/hash/count, not a fabricated prefix. Add a backwards-compatible internal keyword reject_response(brief_id,content,instance,*,received_truncated=False): content=None is accepted ONLY with the true truncation flag after the same managed API/claim checks, records response_too_large/content=None and settles the request quarantined/invalid_response. Existing string callers keep current semantics. Reject string+true, null+false, non-bool flag and all other combinations/extra keys without any diagnostic or state effect. A CLI seat bearer on this reject route gets403 and byte-identical files. Trust boundary: the managed wrapper holds the API seat bearer, while the API model has no tools/bearer access; the server still enforces that bearer holder's adapter and exact claimed dispatch. No unforgeable distinction is claimed between two actors holding the SAME bearer. This approved service-interface amendment remains unimplemented until the payload/test gate.

### Approved revision-parent context amendment

The current private brief freezes expected_parent metadata, but its exact delivery schema contains no parent Markdown. A revision producer needs the previous authored version. Approved service.get_parent(brief_id,instance)->{parent:null|{version_id,sequence,sha256,byte_length,markdown}} uses the same claimed/live producer, channel and packet availability checks as get_brief but is STRICTLY READ-ONLY: no _activate/state sync, service diagnostic, queue effect or durable write. Resolve ONLY audit.expected_parent.version_id and verify actual stored bytes against stored sha256/byte_length AND audit.expected_parent version_id/sequence/hash; no version id is accepted from an agent. Missing/corrupt/mismatched bytes refuse generation with a fixed error, never truncate. Parent is at most512KiB; combined tool cap is stated above. A fresh lineage returns null. This adds an assigned source read, not permission to browse/list the operator library; the parent has already been frozen by compare-and-set and cannot change. CLI gets this value in its brief-tool response; the API worker fetches it through the assigned parent route before assembling model messages, treating the Markdown as UNTRUSTED DATA exactly like the packet. The sealed request/brief/index formats stay unchanged; exact parent body/hash is already retained in the immutable version object and backup lineage. Test wrong seat, unclaimed/terminal dispatch, changed parent metadata, unavailable body, exact CRLF/hash and no side effects. This approved authority-interface amendment remains unimplemented until the payload/test gate.

## Cancellation and factory boundary

API artifacts use the same cancel_requested callback, owned invocation child and InvocationCancelled(local_ended) result. Send cancellation_receipt(local_ended) ONLY after actual local cleanup proof; unresolved stays unresolved, never release-success or generation. The idle loop's current implicit local_ended must not be applied to an artifact left unresolved by a prior process. On a cancelling artifact with no current in-memory invocation, inspect existing invocation evidence for this exact runtime/dispatch: ended/never-started evidence may settle; otherwise report unresolved. Late output meets the durable request fence and quarantines, never publishes or regenerates. Remote-provider compute remains unverified.

Generic native CLI cancellation stays unsupported while its child is live, with no pretend per-turn interrupt or successful release. Existing Stop/end-of-worker exact child/worker exit evidence and the service's repair_cancel_fences path handle settlement. No new PID search, parent kill or consumer reassignment. No request row or outbox file substitutes for native exit evidence.

app.configure instantiates ArtifactStore(hold_unreadable=True) and ArtifactBriefStore under the owned data directory; binds store policy to the existing closed lifecycle getter before catalog initialization. After engine/manager/channel service exist, construct ArtifactService with the shared registry/root/boundary, bind AgentTrigger and coordinator getters, then bind agent transport. Startup recovery runs once after the current registry/runtime reconciliation, before server/MCP publication/background claim loops, without adopting or spawning. It may report runtime_unverified for old live workers until their authenticated heartbeat; no automatic regeneration or per-timer admission is added. run.py assigns the same service to mcp_bridge before MCP listeners. Actual startup ordering and held storage must be tested with the real factory.
