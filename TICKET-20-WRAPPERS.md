## Producer transport and MCP surface

Proposed NEW artifact_transport.py owns an explicitly bound FastAPI router, body limits and service error projection. It is the agent-only bridge; the operator library/request/preview/download routes remain a separate package. Every route requires a current authenticated seat bearer, not an operator token, cookie or caller-supplied identity. Exact validated hex path ids, singleton route parameters, no arbitrary URL/path/channel parameters, no-store responses including delivery. Authentication occurs before reads or mutations. Map access403, malformed400, conflict409 and held503, catching conflicts before ValueError; errors never echo exceptions, paths, body text or secret material. Actual middleware tests reject an operator token/cookie on EVERY artifact agent route; later operator routes reject seat bearers symmetrically. A captured-log/error-body redaction assertion must show neither seal secret nor bearer/nonce, including malformed/private-delivery failures. Only the authorized successful internal API delivery response contains its private authority.

Request readers reject malformed UTF-8, duplicate keys, non-finite JSON, extras and oversize before parsing/service mutation. POST artifact-results uses MAX_RESULT_RECORD_BYTES. Combined brief+packet+parent context has a fixed serialized cap of6*(MAX_PACKET_BYTES+MAX_ARTIFACT_BYTES)+MAX_BRIEF_RECORD_BYTES+16384, currently15,974,400 bytes, covering worst-case JSON escaping of2MiB packet plus512KiB parent and bounded brief/metadata. Enforce that bound before sending a CLI tool response; no partial/truncated source or parent. A known transport/client refusal returns a fixed context-unavailable error where a response is still possible, with no generation or fallback. The app cannot infer an undocumented client context window or detect silent client-side truncation; such a client is unsupported for that scope until the operator selects a smaller scope and acceptance proves it. Reject-report transport uses6*MAX_RESULT_RECORD_BYTES+32768 bytes for bounded escaped diagnostic text; this is distinct from the service's smaller encoded-content cap.

MCP adds exactly chat_artifact_brief(brief_id:str,ctx=None) and chat_artifact_submit(brief_id:str,markdown:str,ctx=None), registered in _ALL_TOOLS. Reuse _authenticated_instance, then service.get_brief plus the proposed assigned get_parent, or submit_cli. The brief tool returns {brief,packet,parent}; parent is null for a new lineage. The model supplies ONLY its assigned brief id and authored Markdown. It cannot set dispatch/attempt/parent/scope, producer/model observation, seal, request id, transport state, recovery flag or source metadata. Submission is CLI-only. The result is JSON containing the existing ACK/QuarantineResult or a fixed safe error projection. Retryable CLI validation exposes code=invalid_content, diagnostic_id and received_truncated and leaves ACTIVE; it does not become an admitted result. Terminal/state/claim refusals tell the agent to stop, with no chat fallback. Instructions state the512KiB UTF-8 cap and preserve exact CRLF/Unicode; no1000-character summary limit applies.

chat_queue_release remains separate transport settlement, never submission. An invalid retryable tool call must not release the dispatch automatically. Successful submission receives ACK first, then the agent calls chat_queue_release with the injected dispatch id. Premature release refuses any later submission immediately because the claim is no longer active; failed/delivery_unconfirmed request settlement occurs only at explicit resume or the one startup pass, not synchronously in the existing release tool. Existing ordinary chat tools remain available but cannot complete artifact requests. MCP global instructions and purpose-specific prompts explicitly prioritize the assigned artifact contract over the existing ordinary-chat response instruction. Tool registration exposes both names to every MCP seat, so protection is the authenticated claim/seat/capability gate, not hiding names. Add named test_artifact_tools_are_registered_and_all_legacy_tools_remain, update any existing tool-list enumeration explicitly and retain every legacy tool; include the real list_tools path used by test_mcp_proxy rather than relying on a hand-maintained count.

## CLI branch and active transport

cli_worker passes its owned runtime path and verified birth/snapshot capability declaration to _queue_watcher through new optional keyword arguments; unmanaged callers retain defaults that cannot execute artifact work. wrapper.py checks purpose BEFORE review_brief_id. Absent purpose follows the byte-compatible legacy path. Unknown purpose or missing managed capability refuses, with no injection or chat fallback. The artifact prompt contains only validated owned ids, tool names, source-is-data instructions and explicit submit-then-release ordering. It does not append chat_send, job routing or mutable recent-chat/rules/source text.

Before a first artifact injection, a configured artifact_worker preflight validates envelope fields against the live claimed server brief and immutable runtime. The source packet is not embedded in the injected line; the agent retrieves it through its assigned MCP tool. CliConsumer gains an optional artifact preflight callback while its default ordinary/review behavior remains unchanged. A definitive preflight403/409/validation refusal before injection releases failed/local_delivery_failure, never claims uncertain keystrokes. A timeout/503/OSError BEFORE injection returns wait, with no permanent hold latch and one retry on the next normal watcher poll; inject only after fetch succeeds. No inner retry loop or new timer is added; HTTP calls retain bounded deadlines and source/body caps. After possible injection or an injection-ACK failure, hold instead and never replay keystrokes. Unknown/malformed purpose cannot execute the callback as ordinary work.

Activation at claimed validation is intentional: the public get_brief preflight transfers and validates the bounded full packet and syncs the request ACTIVE before the agent's later MCP read; private API delivery also activates before parent fetch. A corrupt revision parent may therefore leave a claimed ACTIVE request, although get_parent itself stays read-only. A definitive pre-generation parent/delivery refusal returns the reasoned API held/artifact_context_unavailable outcome and failed release from the table below; A-1 settles failed/delivery_unconfirmed at resume/startup, or the operator can cancel. This does not claim preflight is metadata-only or that all parent failures preserve prepared/queued state.

Inspect ArtifactOutbox in that exact runtime BEFORE requesting a generation brief. If a result already exists, redeliver the same record through POST artifact-results using deliver_saved_artifact, including ACK-only replay for fulfilled requests. Successful redelivery releases transport normally; a terminal QuarantineResult records its disposition and ends work without generation. A diagnostic-only conflict holds the saved record for operator action, with no terminal disposition. A local ACK alone does not permit rewriting content. No review status=saved shortcut is used for artifacts.

Preserve single injection within the live CliConsumer and the ledger's original consumer ownership. A new worker/watcher has a new consumer and cannot inherit or guess the old claim. An acknowledged/uncertain artifact seen without matching in-memory injection evidence must not be injected again when no saved result exists; retain uncertainty for the existing exact-exit/operator path. This proposal adds no durable CLI injection journal or consumer-id persistence. Two mandatory concrete tests: (1) the SAME watcher process sees its same acknowledged/uncertain artifact again with no saved result and injects exactly once total, including injection-before-ACK uncertainty; (2) a RESTARTED watcher gets a new consumer, its claim of that active record raises QueueBusy and it never injects. If either fails or another supported restart can replay injection, stop before implementation continues and return a bounded journal proposal for review.

### Worker validation, messages and errors

The returned envelope keeps its original fields; only validated ids are used in prompts. Reject review routing fields/job_id, unknown purpose, and nonempty text/prompt on an artifact. The existing AgentTrigger sender='?' and text='' are allowed, as are the queue's created_at/target_agent_name/target_identity_id. Nothing is injected or sent by this function.

### CLI callback contract

Transient pre-injection wait is distinct from post-injection hold.

Callbacks: fetch_brief(brief_id)->the exact public get_brief {brief,packet}; submit_saved(record)->ACK|QuarantineResult or an HTTPError/OSError from actual bounded transport. No callback receives a token, private secret or routing authority as a function argument. The HTTP adapter captures its own authenticated transport. Callback test doubles must be labeled, and a function that must not run raises AssertionError so redelivery cannot silently generate/read context.

If private validate_brief is reused to check it, obtain the nonce only from the worker's own immutable runtime locally for validation; never demand it from the public response, include it in messages or widen the MCP projection.

Order: validate managed dispatch ONCE per poll; reuse that validation inside the poll, with no binding cache across polls. Inspect that runtime's ArtifactOutbox FIRST; if a saved record exists, call deliver_saved_artifact with unchanged bytes and submit_saved, returning complete on validated ACK. An existing terminal disposition returns reject/artifact_result_quarantined without new fetch/injection. A terminal server quarantine returns that reject only after disposition durability; the queue mapping below treats prior CLI work as potentially busy. A diagnostic-only quarantine/conflict returns hold without a terminal disposition. Invalid ACK/network/local ACK failure while delivering an existing result returns hold and preserves bytes. Fetching a FIRST brief: definitive403/409/validation -> reject; timeout/503/OSError -> wait/artifact_context_unavailable, no latch. An already injected acknowledged dispatch -> wait/null (normal ongoing console work); injection attempted with uncertain/dispatched receipt after ACK failure -> hold. held_dispatch_id==dispatch or acknowledged/uncertain without matching live injection evidence -> hold. Only a fresh dispatched result-less record and matching public brief/packet may return inject. Cancelling never injects and uses the cancellation branch. No saved record is replaced.
