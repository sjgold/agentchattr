# Correct the source and restart

After **Stop review** settles to stopped or unresolved, expand **Correct source and restart**. Edit the full source and choose **Save corrected source and prepare**. The original source, accepted results and operator answers remain in history. A linked replacement keeps the frozen goal, design, rules and role settings, with an empty result history.

Preparation saves the replacement without dispatching review work. Unchanged source is rejected; same-source turn retry belongs to the later Retry feature. Invalid or oversized input stays in the editor. Pasted source has a 512 KiB UTF-8 limit.

## Prepare the team

The prepared panel offers a frozen source preview, the preserved original review, and **Review or change role contexts**. It distinguishes ready, launching, blocked, unsupported and confirmation-needed roles.

- API roles retain their matching owned supervisor. Each review request uses the frozen replacement packet and its own accepted phase results, excluding shared chat and old answers.
- CLI roles need an explicitly verified adapter contract for a fresh context. Generic native adapters remain unsupported. A new process alone does not certify clean context.
- Replacing a running owned CLI requires a checkbox bound to its exact launch. The worker ends its own client; verified local exit precedes fresh launch. Native login homes, credentials and history files are preserved.
- An unavailable or unknown original launch requires an explicit current managed-seat selection. Selecting a replacement freezes that launch's settings. Unrelated queued or active work blocks a destructive context replacement.
- Human roles continue through the operator result controls.

Choose **Prepare selected contexts** after role changes. Start stays disabled while choices are unsaved or a required context lacks readiness and clean-context evidence. A failed preparation can retain successful contexts; retrying the same operation repairs bookkeeping without allocating another replacement run. Failed owned launches expose a separate explicit preparation retry when safe. Arbitrary server restart adoption remains future work.

## Start or stop

Choose **Start corrected review** once all roles are ready. The server checks their current identities, ownership and unrelated work again. Stopping or unresolved old work cannot be bypassed with a warning acknowledgment. Execution requires proven local termination or an explicitly selected independent clean replacement.

**Stop review** stays available during preparation. Once saved, that Stop permanently prevents the prepared run from activating. Old attempt fences stay permanent after successful correction too. Late old output remains quarantined and cannot become a new result or trigger mention cascades.

Default API/MCP review reads expose only the current corrected run. Fresh CLI identities receive this read boundary before their first boot reads, including the interval before readiness bookkeeping is saved. This protects application context; it does not sandbox a native client's filesystem or erase its external history. Native client and Linux/Omarchy compatibility require separate acceptance.
