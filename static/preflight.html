Checking agents…

These checks only look for programs. They do not start agents, install anything, sign in, or send model requests. Finding a program does not mean it is ready; unknown stays unknown until a launch shows more.

2Choose your team

How seats, launches and settings work

A team mixes API seats and interactive CLI seats. API launch starts a chat adapter; CLI launch opens the configured client in a Windows console or an owned tmux session. Sending instructions can consume provider usage.

Templates come from configured agents. CLI model and reasoning controls require an explicit argument contract. Typed model IDs are unverified. Saved edits apply on the next launch; a running seat needs an explicit restart.

CLI launch writes MCP identity settings and keeps backups of intentional file edits. Native logins are reused. A client with a fixed shared settings file can run one owned seat at a time; conflicting seats require an isolated client profile.

Unticking Use leaves a seat out of this launch only. Its saved settings stay in the team, and an already running seat keeps running until you stop it.
